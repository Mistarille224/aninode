# Web UI localization

The Web UI uses English directly in the source code as its source and fallback language. There is no English locale file and no build-time i18n dependency.

At startup, the UI reads `navigator.languages`. A Chinese browser loads `/assets/locales/zh-CN.json`; unsupported languages keep the English source text unchanged. If a locale file is missing or cannot be loaded, the UI also falls back to the English source text.

Community locale packs live in `internal/server/web/locales/<locale>.json` and are embedded into the binary. Each locale file groups complete English source phrases by UI area under `messages`. The browser flattens those groups when loading the pack. A translation matches only its complete source phrase; it never replaces a word inside another phrase. Dynamic sentences use complete templates with named placeholders, such as `"Season {number}"`.

Run `go run ./scripts/check-i18n.go` after changing UI copy or a locale pack. The check catches missing literal translations, duplicate keys, padded fragments, mismatched placeholders, and changed product names. Keep technical values such as file paths, source titles, and downloader task IDs as placeholders or unmodified data.

To add a language:

1. Add `internal/server/web/locales/<locale>.json` using the same schema as `zh-CN.json`.
2. Add the locale match to `preferredLocale()` in `internal/server/web/i18n.js`.
3. Keep all new user-facing source strings in English in the HTML/JavaScript. Add complete translations to a named group in the locale file. Use `formatMessage()` for sentences containing dynamic values, then add the complete source template and its translation.
4. Run `go run ./scripts/check-i18n.go`.

`zh-CN.json` is the reference community translation pack and contains the Simplified Chinese UI.
